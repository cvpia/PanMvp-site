WIKI / PANMVP 0.2.4

PanMVP 使用说明书

从首次运行到 115 账号、播放、影院刮削、任务和日志排障。以 Windows 本机运行为主，同时提供官方 Docker 镜像。

快速开始

登录页、初始化页和控制台顶栏都会显示当前版本号，可用于确认本机或 Docker 部署的是哪个版本。

推荐使用项目自带的 PowerShell 脚本：它会创建 backend/.venv、安装依赖、构建 Vite 前端并启动 FastAPI。

Set-ExecutionPolicy -Scope Process Bypass
.\scripts\local.ps1 setup
.\scripts\local.ps1 start

浏览器打开 http://localhost:8787，首次运行会引导创建管理员账号。常用命令：

.\scripts\local.ps1 status
.\scripts\local.ps1 start -Reload
.\scripts\local.ps1 test
.\scripts\local.ps1 stop
发布提示：PanMVP 官网与 Wiki 是纯静态站点。访问官网不会连接你的本机数据库，也不会下载或公开源码。

关于版本

登录后点击左侧导航“关于版本”，可以查看后端当前运行版本、最近版本更新、发布规则和官方资源入口。该页面通过 /api/setup/status 动态读取版本号，不依赖前端写死。

  • 当前版本：显示正在运行的后端版本，并提供“刷新版本信息”按钮。
  • 版本记录：集中展示近期功能更新，每次代码改动递增补丁版本后同步新增记录。
  • 一致性提示：如果后端版本与前端版本记录不一致，页面会提示刷新或重新构建部署。
  • 官方链接：可打开官网 Wiki 和 Docker Hub 镜像标签页。

安装与升级

环境要求

  • Windows 10 / 11 或可运行 Python、Node 的 Windows 环境。
  • Python 3.12+；项目默认使用 backend/.venv。
  • Node.js 20+；项目可使用仓库内 .tools/npm。
  • 可选：FFmpeg / FFprobe，用于 HLS、字幕和媒体探测。

手动开发运行

cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[test]"
uvicorn app.main:app --reload --port 8787
cd frontend
npm install
npm run dev

升级

获取新版本后重新执行 .\scripts\local.ps1 setup，再启动服务。数据库和 data/ 目录会保留；升级前建议备份 data/panmvp.db。

Docker 镜像部署（可选）

除本机运行外，PanMVP 提供官方镜像 xxoo520zls/panmvp:0.2.4（滚动标签 xxoo520zls/panmvp:latest）。镜像内置 Python 3.12、FFmpeg、Vulkan 软件驱动（lavapipe）与构建好的前端，宿主机无需安装 Python、Node 或额外显卡驱动。

启动容器

docker run -d --name panmvp `
  --restart unless-stopped `
  -p 8787:8787 `
  -v panmvp-data:/data `
  -e PANMVP_SECRET_KEY="<32 位以上随机字符串>" `
  -e PANMVP_PUBLIC_BASE_URL="http://localhost:8787" `
  xxoo520zls/panmvp:0.2.4

浏览器打开 http://localhost:8787，首次运行同样会引导创建管理员账号。

  • /data 是唯一必须持久化的目录，保存 panmvp.db、local.secret 和 logs/。
  • 未设置 PANMVP_SECRET_KEY 时，容器首次启动会在 /data/local.secret 生成随机密钥并复用；设置后不要随意更换，否则旧密文无法解密。
  • PANMVP_PUBLIC_BASE_URL 影响 STRM 播放地址和分享链接，局域网访问请改成 http://内网 IP:8787。

挂载 STRM 输出目录

STRM 生成写入的是容器内的“本地输出目录”，需要把它映射到宿主机磁盘：

docker run -d --name panmvp `
  -p 8787:8787 `
  -v panmvp-data:/data `
  -v D:\Media\strm:/strm `
  xxoo520zls/panmvp:0.2.4

然后在“系统设置 → STRM 生成”里把本地输出目录填成容器内路径 /strm，不要填宿主机路径 D:\Media\strm。

运维、升级与备份

docker logs -f panmvp     # 查看应用与容器日志
docker restart panmvp     # 重启
docker rm -f panmvp       # 删除容器，数据卷保留

docker pull xxoo520zls/panmvp:0.2.4
docker rm -f panmvp       # 再用相同参数重新创建容器

docker run --rm -v panmvp-data:/data -v ${PWD}:/backup alpine `
  tar czf /backup/panmvp-data.tgz -C /data .
注意：Docker 只是可选运行方式，PanMVP 不使用容器编排；数据库、凭据和日志始终保存在你的数据卷中，不会上传到第三方服务。

115 网盘配置

  1. 进入“系统设置 → 115 网盘”。
  2. 推荐选择扫码客户端，点击“获取二维码”，用 115 App 完成扫码确认。
  3. 登录成功后检查个人资料卡：真实头像、用户名、账号 ID、会员到期时间，以及从 115 个人空间接口读取的总容量、已用和剩余空间。
  4. 设置默认转存目录，点击“保存账号设置”。如果默认目录未设置，首次添加资源时会先弹出默认目录设置窗口。
  5. 永久 VIP 会显示金色“永久会员”标识；普通 VIP 显示到期时间。

Cookie 直填

也可以填写类似下面的 Cookie。Cookie 只会加密写入本机 SQLite，前端不会回显原文。

UID=...; CID=...; SEID=...; KID=...
安全：不要把 Cookie 发到公开聊天、截图、Issue 或 GitHub Pages。该信息等同于账号会话凭据。

文件管理页面的网盘标签

标签会显示“115 网盘 + 网盘用户名 + 账号 ID”，便于区分多个账号和排查连接状态。

资源搜索、自动转存与订阅

默认转存目录与弹窗开关

资源添加默认使用“系统设置 → 115 网盘 → 默认转存目录”，不会强制打开 modal-backdrop 目录窗口。

  1. 在 115 账号设置中保存一次默认转存目录。
  2. 进入“系统设置 → 基础设置”，确认“资源添加时显示目录选择弹窗”保持关闭。
  3. 在资源搜索中点击“添加”，系统直接按默认目录执行分享转存或 115 云下载，成功提示会在几秒后自动消失。
  4. 如果默认目录从未设置，系统会先弹出默认目录选择窗口；保存后自动继续当前资源操作。
  5. 需要逐次选择目录时，再开启该弹窗开关；关闭后恢复默认目录自动转存。

磁力链接与电驴链接

磁力链接和电驴链接统一提交 115 云下载，保存到默认目录。一次资源返回多个链接时，只提交文件最大的一个；订阅任务也会优先选择文件最大的可访问资源。

聚影自动登录

聚影账号只需在“系统设置 → 资源登录”保存一次。Token 失效时，后端会使用已保存账号密码自动重新登录、加密保存新 Token 并重试当前请求；自动登录失败时再提示重新登录。

订阅成功 / 已转存资源

左侧导航新增“转存成功”页面，集中展示订阅匹配后已转存或已提交云下载的记录，包括影片、网盘、目标目录、转存方式和时间。

文件管理

操作说明
浏览 / 打开进入 115 文件夹，根目录开始按真实目录浏览。
下载单选文件，通过签名票据下载，支持 115 直链解析。
批量重命名先预览新旧名称，再确认执行；不会绕过 115 官方接口。
批量分享调用 115 官方分享接口，可设置标题、提取码和有效期。
删除支持多选删除；根目录不会删除。
播放支持常见视频文件进入 PanMVP 播放器。

涉及写操作前会弹出确认，并记录按钮动作日志；API 请求和错误也会出现在运行日志页面。

目录树 STRM 生成

进入“系统设置 → STRM 生成”，每个映射保存一条 115 来源目录到本地输出目录的关系。系统直接递归读取 115 目录，不再调用官方目录树导出接口。

配置映射

  1. 点击“新建映射”，选择 115 网盘和默认生成方式。
  2. 点击“选择目录”打开 115 目录弹窗；可浏览、进入或新建 115 文件夹。
  3. 点击本地“选择目录”打开本机目录弹窗；可选择磁盘、浏览或新建输出文件夹。
  4. 保存映射。目录树清单写入本地输出目录的 .panmvp/directory-tree.json。

两种生成方式

方式行为
目录树 + STRM 全量生成重新扫描来源目录，重建全部 STRM，并更新本地目录树清单。
直接 STRM 增量生成仅写入新增或发生变化的视频，跳过未变化项，并清理来源中已删除的旧 STRM。
旧版清理：“清理旧官方目录树文件”只删除旧任务中名称包含“目录树”的 115 导出文件，并清理本机旧缓存，不会删除媒体文件。

播放链路

302 直链

服务端解析 115 播放地址并返回 HTTP 302。浏览器直接从网盘读取媒体流，服务器压力较小，适合大多数家庭网络。

代理播放

兼容防盗链或局域网问题，服务端完整转发 Range、Content-Range、Accept-Ranges 和 206 响应，支持拖动。

HLS 回退

302 失效时，可使用本机 FFmpeg 生成 HLS。多音轨会被映射为可切换轨道，缓存会在播放结束后清理。

影院播放器保留上下黑色背景，播放按钮、控制按钮和文字使用高亮青色与发光边框，避免在黑色区域中难以区分。杜比 Vision 会通过 libplacebo 处理 Dolby Vision 元数据并转为 BT.709 SDR；HDR10/HLG 使用 zscale + tonemap。若自动转码失败，HDR/DV 会停止播放并提示原因，避免回退直链后再次偏色。

场景建议
家庭内网、直链可用使用 302，速度最快。
播放器提示 403 / 源站防盗链切换代理播放或检查网络代理。
需要多音轨 / 字幕转码配置 FFmpeg / FFprobe 并使用 HLS。

影院与 TMDB 刮削

v0.2.1 的影院刮削固定使用 TMDB，不再回退其他元数据源。首次使用前请在“系统设置 → 高级设置”配置全局 TMDB API Key，或在个人偏好中配置个人 Key。

入库流程

  1. 点击“影院 → 入库 115 目录”。
  2. 选择一个或多个来源目录，确认是否删除所选来源的旧本地 STRM。
  3. 系统直接扫描 115 目录，并依次创建目录树、STRM 生成和刮削任务。
  4. 任务中心显示每阶段进度；完成后影院卡片实时出现。

独立 TMDB 刮削器

  • 清洗分辨率、编码、发布组、语言等发布文件名信息。
  • 识别 TMDB ID、IMDb ID、年份和剧集季集号。
  • 按标题、年份、类型、热度、票数和海报信息评分候选。
  • 补全详情、演员、导演、类型、片长、评分、海报和背景图。
  • 生成 Emby / Kodi 兼容 NFO。

手动校准

在影院详情页点击“手动校准刮削”，输入标题、年份和类型，搜索 TMDB 候选。点击候选卡片后，系统会绑定 TMDB ID，保存时同步更新数据库、NFO、海报和背景图。

没有 TMDB Key：影院条目仍可显示原始解析结果，但无法自动补全元数据和海报；搜索候选会提示“请先配置 TMDB API Key”。

任务中心与运行日志

任务中心

显示执行中、已完成、失败和暂停状态。影院任务支持断点继续；订阅任务支持重试。新版本提供“一键删除”，确认后会停止运行中任务并删除当前账号任务记录。

一键删除不可恢复：删除的是任务记录；已经生成的本地 STRM、NFO、海报等文件需要到影院来源管理中处理。

运行日志

日志包含按钮动作、API 请求、任务执行、状态码、耗时、用户和错误。日志按日保存，可在页面设置保留天数和每日清理时间。

日志类型用途
button_action记录页面按钮点击及上下文。
http_request记录 API 路径、方法、状态码、耗时和请求 ID。
task / cinema / playback记录任务执行、影院刮削和播放相关事件。

通知渠道

支持 Telegram、企业微信、钉钉、邮件和通用 Webhook。配置后，任务完成或失败可发送通知；通知凭据加密保存。

  • Telegram：填写 Bot Token 和 Chat ID。
  • 企业微信 / 钉钉：填写机器人 Webhook。
  • 邮件：填写 SMTP 地址、账号、密码和收件人。
  • 通用 Webhook：适合接入自建服务或自动化平台。

安全与隐私

  • 为生产环境设置稳定的 PANMVP_SECRET_KEY，用于加密 115 Cookie、通知凭据和 TMDB Key。
  • 不要把 .env、data/panmvp.db、Cookie、日志或截图提交到公开仓库。
  • GitHub Pages 只部署 docs/ 静态站点，不包含后端源码或运行数据。
  • 公网访问时应在反向代理层启用 HTTPS，并限制管理接口来源。
  • 资源搜索依赖用户自行配置的账号；PanMVP 不内置或分发盗版资源。

故障排查

115 显示连接异常

  1. 检查是否已扫码或填写 Cookie。
  2. 在 115 网盘设置中点击“刷新信息”和“检测连接”。
  3. 若 Cookie 过期，重新扫码登录。
  4. 检查系统代理是否能访问 115.com 和 webapi.115.com。

影院刮削没有海报或信息

  1. 确认已配置 TMDB API Key，并在设置中测试网络。
  2. 检查文件名是否包含可识别片名、年份或 TMDB/IMDb ID。
  3. 在影院详情中使用“手动校准刮削”选择正确候选。
  4. 查看运行日志中 cinema_poster、cinema_scrape 的错误信息。
  5. 日志出现 All connection attempts failed 时，在“系统设置 → 基础设置 → 网络代理”填写可用代理，该设置对所有外部请求生效。
  6. 没有匹配到海报的条目会显示占位图，并在 6 小时冷却后才重新尝试。

播放卡顿 / 无法拖动

  1. 切换 302 / 代理播放模式。
  2. 检查网络带宽和代理稳定性。
  3. 拖动失败时确认服务端代理是否透传 Range。
  4. HLS 场景检查 FFmpeg 路径是否可执行。

任务一直排队或失败

  1. 查看任务卡片的错误和运行日志。
  2. 确认数据库目录可写、磁盘空间充足。
  3. 影院任务失败后可使用“继续”从断点恢复。
  4. 必要时删除任务后重新创建任务链。

常见问题

可以部署到公网服务器吗？

PanMVP 以本机（含本机 Docker）运行为主，不提供集群编排。若通过反向代理暴露，请自行启用 HTTPS、访问控制和备份策略，并把 PANMVP_PUBLIC_BASE_URL 指向真实访问地址。

Docker 运行和本机运行有什么区别？

功能完全一致：Docker 镜像内置 Python、FFmpeg 和已构建前端，省去本机环境安装；本机运行便于直接改代码和调试。两者共用同一套 SQLite 结构，数据分别保存在本地 data/ 目录或 Docker 数据卷中。

官网会公开源码吗？

不会。GitHub Pages 工作流只上传 docs/ 目录中的静态网站文件。后端、数据库、日志和凭据不会进入 Pages artifact。

为什么影院刮削必须是 TMDB？

为了统一元数据结构、减少错误匹配并稳定生成 Emby/Kodi 兼容 NFO，影院链路只使用 TMDB。发现和订阅模块仍可保留其他来源。

如何反馈问题？

提交问题时请附版本号、操作步骤和脱敏后的运行日志。不要上传 Cookie、API Key、数据库或包含隐私的截图。
